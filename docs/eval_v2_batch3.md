# 评测集 v2 · 第三批（预算 3 条 + 持妆 3 条 + 硬约束 3 条 + 质地 3 条）

> 结构对齐第一批/第二批（docs/eval_v2_batch1.md / eval_v2_batch2.md）。
>
> - **预算/比价型（P）** = 预算约束 → 挡位推荐 + 对比 + **价格诚实标注**（库里 77% 商品无价格，不能瞎报价）。**价格本质是入库快照：真实场景必须接实时价格 API（库存/优惠同理），库内价格需定期更新**——评测只验证「引用可检索的价格 + 诚实标注价格状态」，不验证实时价格本身。
>   **预算型也先问清（2026-08-27 用户定）**：预算 Query 常只给「预算+遮瑕」——**信息极缺时（肤质/妆效/色号全缺，如 P-3）必须强制追问**（对齐 F-1 合并式，先给友好预期），只凭「预算+遮瑕」就推荐=瞎猜；**约束较全时色号设软追问**（如 P-1/P-2）：推荐末尾附一句「告诉我常用色号（偏自然/偏白）可更精准」，不强制、给到即加分。**色号尤其重要**：预算内选项少，色号不对等于白推。
> - **持妆/场景型（W）** = 持妆时长 / 防水 / 户外 → **场景归因**（v13 隐藏意图：去海边 → 防晒+防水）+ 持妆约束。
> - **硬约束型（H）** = 敏感肌/痘痘肌/复合肤质 → 硬过滤 + **诚实兜底**（需求在库内无解时直说，不硬凑）。
> - **质地/形态型（T）** = 粉状/液体/气垫 → `form_tag` 强硬约束。
> - 素材来源：持妆型 2 条升级自真实 need（id=9 / id=3），质地型 1 条真实（id=6）；预算/硬约束/其余质地为**模拟客服咨询场景**（评论区只有「买了觉得值」的反馈句，没有「帮我找预算内的/只要粉状」这类咨询 need 句，已标注）。
>
> 每条推荐/避雷商品均已核对真实商品标签 + 领域常识。
>
> **推荐证据四件套（2026-08-27 用户定）**：每行推荐证据 = **标签 + 价格 + 口碑 + 热度**，末尾带 **🔗 asin 链接占位**（真实场景拼 `https://www.amazon.com/dp/{asin}` 跳转商品页）。热度按评论量分档：**高 ≥200 / 中 50-199 / 低 <50**。**活动/促销价：库内无此字段 → 标「需实时 API」不虚构**（对齐「价格=快照，真实场景接实时价格 API」约定）。
