# Phase 1 检索层 · 段 A 报告（轻量三模式消融）

> 生成：2026-08-27 ｜ 脚本：[retrieval_engine.py](retrieval_engine.py) / [eval_retrieval.py](eval_retrieval.py) ｜ 数据：`data/retrieval_ablation.csv`
> 段 B（向量）待 torch + bge 安装后补齐四模式消融。段 A 是「零安装跑出可评测基线 + 发现核心问题」。

---

## 1. 评测设置（为什么在候选池内算）

- 11 条 need query × `candidate_pool`（每 query 金标准 67 全量 + 50 负候选：难例 15 / 随机 35）
- 三模式：**bm25**（手写 BM25，title+brand 英文文档）/ **tag**（标签匹配分，知识分层）/ **mixed**（BM25×0.3 + 标签×1.5 + 热度×0.3 + 动态路由偏置 + 置信度降权）
- 指标：NDCG@5 / Recall@5 / MRR / 避雷准确率（均候选池内）
- **意义**：全库 1090 里相关商品占比过低，排序随便排前面 NDCG 都高；候选池里塞满金标准 + 干扰项，排序质量才分得开（对标 Amazon-C4）

## 2. 消融对比表

| 模式 | NDCG@5 | Recall@5 | MRR | 避雷准确率 |
|---|---|---|---|---|
| bm25 | **0.014** | 0.019 | 0.108 | 0.815 |
| **tag** | **0.652** | **0.694** | **0.818** | 0.741 |
| mixed | 0.445 | 0.495 | 0.678 | **0.926** |

> mixed 首版 α=1.0 只有 0.394（BM25 噪声稀释标签分）→ α 降到 0.3 后 0.445。调参记录本身就是消融价值。

## 3. 三大发现

**发现 1：BM25 对真实长句 query 失效（NDCG 0.014）——词汇鸿沟的实证。**
评论抽取的 query 是自然语言长句（"I'm over 60 and my skin is blotchy..."），商品标题是营销词（"Full Coverage Cream Compact Foundation, Waterproof Long Wear"），两者几乎零词汇重叠。**这反证了结构化标签检索的必要性**：没有标签体系，光靠词面匹配真实需求是抓不到的。

**发现 2：标签分（知识分层）是核心检索信号（0.652）。**
肤质/妆效/遮盖/质地/色号五轴 + 隐式意图 + 置信度降权，把「用户症状」映射到「商品属性」——这是本项目区别于「embedding 一把梭」的独特点：**结构化维度可审计、可归因**（每条命中带 reason）。

**发现 3：mixed 的避雷准确率最高（0.926）——负向约束在混合里最强。**
单一标签模式避雷 0.741（负向扣分不够），混合后热度 + BM25 + 路由偏置共同压住错误推荐。**「检索质量看 NDCG，业务安全看避雷准确率」**——这正是导购场景区别于通用搜索的地方。

## 4. Badcase 分析（段 B 的改进清单）

| query | 现象 | 根因 | 段 B 对策 |
|---|---|---|---|
| q9 坎昆防水防晒 | MRR 0.125，gold（bareMinerals SPF15）沉底 | 候选池 0 难例（无显式标签轴）+ 隐式「防晒」只有 +1 加分 | query_rewrite（"waterproof + SPF"）向量相似度抓语义 |
| q1 高遮瑕·斑驳肌 | NDCG 0.152，primary 没进 top5 | 候选池 15 个难例全是「高遮瑕」，标签分区分不开，热度权重低 | 向量 + 提高热度权重，约束敏感度（光泽/熟龄） |
| q7 轻质控油粉饼 | NDCG 0.303，Mirenesse 重复上榜 | 「控油」隐式 +1 不足以把「哑光粉状」顶上去 | 隐式意图权重升级（控油 → 哑光 +2） |
| q10/q11 纯避雷 | Recall nan（无正例），避雷 0.667 | 无 primary 纯负例，MRR 无意义 | 评测口径：避雷题只看「避雷准确率」，不算 NDCG |

## 5. 为什么需要向量（段 B 的核心动机）

BM25 0.014 说明**词面匹配救不了真实 query**；标签分 0.652 说明结构化维度是主力，但 q9 证明**隐式意图/语义场景（去海边→防晒+防水）必须靠向量语义相似度兜底**。
段 B 计划：
1. 装 torch + sentence-transformers + bge 模型（hf-mirror）
2. 商品文档（title+brand+标签）embedding + query_rewrite embedding
3. 四模式消融：bm25 / 向量 / mixed / mixed+重排 —— 预期向量把 q9/q1 拉起来
4. mixed 权重正式调参（α/β/γ 网格）

## 6. 阶段口径（段 A）

> 「我用 Amazon-C4 的方式建了候选池（金标准 + 50 负候选，含难例分层），检索层先做了三模式消融：BM25 对真实长句 query 基本失效（NDCG 0.014，词汇鸿沟实证），结构化标签分是核心信号（0.652，逐轴可归因），混合模式避雷准确率最高（0.926）——所以检索的核心不是 embedding 一把梭，是『维度可审计 + 负向约束可自证』；向量检索作为语义兜底补上 q9 这类隐式意图场景。」
